# Какую коллекцию выбрать — C# Fundamentals

Коллекция выбирается не по привычке, а по тому, что вы с ней делаете чаще всего.

## Быстрая шпаргалка

| Задача | Тип | Поиск | Почему |
|---|---|---|---|
| Просто список по порядку | `List<T>` | O(n) | Индекс, сортировка, минимум накладных расходов |
| Проверять «есть ли элемент» | `HashSet<T>` | O(1) | Хеш вместо перебора |
| Искать значение по ключу | `Dictionary<K,V>` | O(1) | То же, но с полезной нагрузкой |
| Отдать наружу, запретив менять | `IReadOnlyList<T>` | — | Тип говорит: не трогать |
| Очередь задач | `Queue<T>` | — | FIFO без ручных индексов |

## Ошибка, которая стоит дороже всего

```csharp
// O(n) внутри цикла по n элементам = O(n²).
// На 10 000 записей это миллионы сравнений.
foreach (var id in ids)
{
    if (allLessons.Any(l => l.Id == id)) { /* ... */ }
}

// Один проход на построение множества, дальше O(1) на проверку.
var lessonIds = allLessons.Select(l => l.Id).ToHashSet();

foreach (var id in ids)
{
    if (lessonIds.Contains(id)) { /* ... */ }
}
```

## Про изменение коллекции во время перебора

`foreach` бросит `InvalidOperationException`, если внутри цикла добавить или
удалить элемент. Собирайте изменения отдельно:

```csharp
var toRemove = items.Where(i => i.IsExpired).ToList();
foreach (var item in toRemove)
{
    items.Remove(item);
}
```

## Ленивость LINQ

`Where` и `Select` ничего не считают, пока результат не начнут перебирать.
Поэтому два `foreach` по одному запросу — это два прохода по источнику.
Нужен результат больше одного раза — материализуйте: `.ToList()`.
