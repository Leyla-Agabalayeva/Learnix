# Асинхронность в JavaScript — конспект

## Событийный цикл в одном абзаце

JavaScript однопоточен. `setTimeout`, `fetch` и обработчики событий не
выполняются «параллельно» — они кладут задачу в очередь, а движок берёт её,
только когда текущий код досчитал до конца. Поэтому долгий синхронный цикл
подвешивает всю страницу, включая анимации и клики.

## Три вещи, на которых спотыкаются чаще всего

**1. `await` внутри `forEach` не работает.**

```javascript
// Ничего не ждёт: forEach не умеет обращаться с промисами.
ids.forEach(async (id) => { await save(id); });
console.log('готово');   // напечатается ПЕРВЫМ

// Так — последовательно и предсказуемо.
for (const id of ids) {
    await save(id);
}

// А так — параллельно, если порядок неважен.
await Promise.all(ids.map((id) => save(id)));
```

**2. `fetch` не считает 404 ошибкой.**

Промис отклоняется только когда до сервера не достучались. Код 4xx/5xx —
это успешно полученный ответ, и проверять его нужно вручную:

```javascript
const response = await fetch(url);

if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
}
```

**3. Ошибка в асинхронной функции без `await` пропадает.**

Вызов без `await` и без `.catch()` даёт unhandled rejection: в консоли
предупреждение, в интерфейсе — тишина и пустой экран.

## Мини-задание

Напишите функцию, которая делает три запроса параллельно и возвращает
результат первого успешного, игнорируя упавшие. Подсказка: `Promise.any`.
